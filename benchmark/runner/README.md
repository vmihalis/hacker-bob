# bob-oss benchmark runner

> **Agents: read [`../AGENTS.md`](../AGENTS.md) FIRST.** It is the operational runbook
> (how to run without producing invalid results — especially the Docker/tmux trap that
> silently degrades bob-oss to static-only). This README covers strategy/rationale.

bob-oss attacks **one** repo per invocation. This runner turns that into a matrix:
for each ARVO case in `cases.tsv`, it launches an isolated bob-oss run, scores recall
(via `../scorer.py`, root-cause→Fix_B, optionally oracle-reproduced) and cost (via the
adapter's transcript cost-join), and appends one row to `../results/cybergym_trials.jsonl`
(the legacy non-CyberGym trial-1 stays separate in `../results/spike_trials.jsonl`).
`aggregate.py` rolls that into the comparable headline numbers.

## Strategy — breadth over depth (and why it's also the cheap option)

A recall estimate's precision scales with the number of **distinct cases**, not
trials-per-case. So for *comparing harnesses*, many cases × 1 trial beats few cases ×
many trials — statistically **and** on cost. The field (CyberGym, SEC-bench) reports
single-attempt recall over a large case set; matching that means **k=1 over many cases**.

Operating plan:
1. **CyberGym-JOINED, stratified slice** — `cases.tsv` is generated by
   `build_cybergym_slice.py`: 26 cases, each a real CyberGym `arvo:<id>` task, across 26
   distinct projects and the ASAN corruption classes (heap/global/stack overflow, UAF,
   double-free, …). The target is CyberGym's own `repo-vul.tar.gz`, so bob attacks
   **byte-identical code** to what CyberGym agents attacked ⇒ the comparison is paired.
2. **k=1 headline**, bump a small subset to `n_trials=3` for a variance / pass@k read
   (column 4 of `cases.tsv`).
3. **Difficulty match:** bob gets only the repo (no description/crash/patch) ⇒ that is
   CyberGym **Level 0**. Compare bob to CyberGym's L0 numbers, never the headline aggregate.
4. **Report** single-trial reproduction recall + 95% CI + per-trial precision + as-deployed
   cost/run, **as a lower bound** (bob does open-ended discovery, the harder task), and
   **co-headline the novel-yield track** — bob's *other* real findings on the same repo
   that aren't the planted bug (recall scores them zero; report them separately).

## Cost model

One trial ≈ **$15–25** API-equivalent for a focused parser target (muparser trial-1 was
**$19.54**); large projects can hit $50–75. **On a Claude subscription the marginal
out-of-pocket cost is ~$0** — you pay the flat fee. The real budget is **rate limits
(shared with Bob) + wall-clock time + disk**. The API-equivalent dollar figure is the
benchmark's cost-efficiency numerator ("$/bug"), not money you spend.

`run_matrix.sh` enforces `BUDGET_USD` (default $300 API-equivalent): it sums ledger cost
and refuses to launch a new cell once spend crosses the ceiling. Raise it to continue.

## Setup (once, on the VPS, as the openclaw user)

```bash
sudo -iu openclaw                       # land as openclaw (claude/docker/subscription live here)
# benchmark code synced to /home/openclaw/oss-bench-src/benchmark ; OSS workspace at /home/openclaw/oss-bench
mkdir -p /home/openclaw/oss-bench-runs
# sanity: claude + MCP reachable
cd /home/openclaw/oss-bench && claude mcp list      # expect: bountyagent ✓ Connected
```

## Run

```bash
cd /home/openclaw/oss-bench-src/benchmark/runner
tmux new -s bench                       # survive SSH disconnects

# 1) SMOKE — validate the harness end-to-end on ONE cell before spending on the matrix.
ONLY_CASE=18562 ./run_matrix.sh        # lwan, small tarball (~365 KB), fast
#    PASS = ledger gets a status:complete row with a grade + a recall verdict, and the
#    claude -p process ran the FULL pipeline (build → waves → verify → grade → report)
#    in one shot. If it stops early, run_cell auto-resumes up to MAX_RESUMES.
#    This also exercises TARBALL mode (download repo-vul.tar.gz → descend to repo root).

# 2) FULL matrix (after smoke passes). Tune the knobs:
BUDGET_USD=300 MODEL=opus ./run_matrix.sh
```

Knobs (env): `BUDGET_USD`, `MODEL` (empty = inherit), `USE_ORACLE=1` (independent ARVO
re-exec, +5.78 GB image/case), `CELL_TIMEOUT` (s), `MAX_RESUMES`, `KEEP_REPO_RUNS=1`,
`ONLY_CASE`, `BUILD_FLAGS`. Re-running `run_matrix.sh` **skips completed cells** (idempotent).

## Isolation & recovery

- Each cell gets a distinct `--target-id` (`bench-<case>-tNN`) ⇒ its own session dir, no
  collision across trials. Fallback: newest session dir touched since cell start.
- Each cell runs in a fresh `claude -p` (no context carryover between trials).
- Transcript located by `session_id` from the stream-json log (fallback: newest jsonl).
- `repo-runs/` (fuzzers/corpora, large) is pruned after scoring unless `KEEP_REPO_RUNS=1`.

## Regenerating / expanding the CyberGym slice

The slice is generated (not hand-curated). To rebuild or grow it (needs network + an
authenticated `gh`):

```bash
python3 build_cybergym_slice.py --n 30 --per-project-cap 2 --seed 7
#  - pulls CyberGym tasks.json (HuggingFace), keeps arvo:<id> tasks
#  - stratifies by project (cap) + ASAN crash class; drops MSAN/unknown confounds
#  - enriches via ARVO-Meta (crash_type, fix commit) + GitHub commit API (Fix_B)
#  - writes cases.tsv (runner matrix) + ../cybergym_cases.json (scorer ground-truth)
```
`scorer.py` auto-merges `cybergym_cases.json` into `GROUND_TRUTH_CASES` at import, so
`--case <arvo_id>` resolves for every generated case. Change `--seed` to draw a different
(reproducible) sample; raise `--n` for a tighter CI (≈±0.1 needs ~60 cases at p≈0.2).

For a **non-CyberGym** case (e.g. a fresh ARVO id from the VPS `arvo.db`), use
`register_case.py` (clone repo, `git fetch`, derive Fix_B via `git diff-tree`) and paste
its output into `../scorer.py` + `cases.tsv` manually.

## Comparing to CyberGym

Headline = bob's **single-trial reproduction recall** on this slice vs CyberGym's
**Level-0** recall (top model+scaffold ≈20% on the full 1,507-task set). Because every
row is a CyberGym `arvo:` task, you can also do a **paired** per-case join (McNemar) once
you have CyberGym's per-task L0 results. Always annotate bob's number as a **lower bound**
(open-ended discovery vs directed reproduction) and report off-list real findings
separately. Legacy non-CyberGym cases (muparser 25402 etc.) stay in the ledger as
pipeline-proof datapoints but are not part of the paired comparison.
